# 轻量 Web SSH 工作台产品与需求设计

日期：2026-09-14

## 1. 产品定义

产品暂以“轻量 Web SSH 工作台”为工作名称，首发形态为单个 Docker 实例。它服务于需要管理多台 Linux/Unix Server 的个人开发者、运维人员和小型团队成员，通过浏览器配置并连接不同的 SSH Server。

核心承诺：

> 配置一次，之后从主机列表快速、安全地连接到任何已授权的 Server。

## 2. 用户与场景

### 2.1 首要用户

- 个人开发者：管理家用实验室、云服务器和开发环境。
- 运维/DevOps：在一个自托管入口管理开发、测试、生产主机。
- 小团队管理员：先以单用户实例使用，未来可扩展账号和权限。

### 2.2 关键场景

1. 首次部署后添加第一台 Server。
2. 已保存多台 Server，按名称、IP、标签快速搜索。
3. 在同一浏览器中打开多台 Server 的终端标签。
4. 浏览器刷新或网络波动后恢复连接。
5. 远程 Server 首次出现 host key 或 host key 发生变化。
6. 用户离开设备时锁定凭据库。

## 3. 产品目标与非目标

### 3.1 v0.1 目标

- 使用 Docker 一条命令启动。
- 支持多个 Server 配置和一键连接。
- 支持 SSH 密码、私钥和带 passphrase 的私钥。
- 提供可靠的交互式终端，兼容 `vim`、`top`、`htop`、`tmux` 等常见 TTY 程序。
- 提供分组、标签、收藏、最近连接和多终端标签。
- 对凭据、主机指纹和 WebSocket 会话建立清晰的安全边界。

### 3.2 v0.1 非目标

- 云端账号、云同步和多设备同步。
- 团队邀请、共享 Vault、细粒度 RBAC。
- SFTP 文件管理。
- SSH port forwarding、代理跳转和 X11 forwarding。
- 终端录像、实时协作和远程桌面协议。
- 浏览器内任意执行本地命令或通过 URL 传入远程主机。

非目标不是永久拒绝，而是避免首版偏离“轻量、多 Server、浏览器 SSH”主线。

## 4. 信息架构与界面

### 4.1 页面

1. **初始化/解锁页**：首次创建主密码；后续输入主密码解锁 Vault。
2. **主机工作台**：显示搜索、筛选、分组、最近连接和主机列表。
3. **新增/编辑主机抽屉**：填写连接信息和认证方式。
4. **终端工作区**：多标签终端、连接状态、终端工具栏。
5. **设置页**：锁定、自动锁定、终端主题/字体、已信任主机指纹和数据备份入口。

### 4.2 主机表单

必填：

- 主机名称
- Server IP 或域名
- SSH 端口，默认 `22`
- SSH 用户名
- 认证方式

认证字段：

- 密码认证：密码
- 私钥认证：私钥文本或文件、可选 passphrase

可选：

- 分组
- 标签
- 收藏
- 连接超时时间

表单提供“测试连接”动作，但测试过程不保存明文凭据到日志，也不默认改变主机指纹信任状态。

### 4.3 主机工作台

- 默认按最近连接排序。
- 支持名称、地址、用户名和标签搜索。
- 主机卡片展示名称、地址、端口、用户、认证类型、最近连接状态。
- 密码、私钥内容和 passphrase 永远不展示在列表和普通详情中。
- 收藏主机置顶；分组可折叠。
- 空状态直接提供“添加第一台 Server”按钮。

### 4.4 终端工作区

- 一个主机对应一个终端标签；同一主机允许打开多个标签。
- 标签显示主机名称和连接状态：连接中、已连接、重连中、已断开、失败。
- 终端使用深色默认主题，但提供浅色主题和字号调整。
- 支持复制、粘贴、全屏、终端搜索、清屏和重新连接。
- 浏览器尺寸变化同步远程 PTY 的列数和行数。
- 页面刷新后尝试在短暂保留窗口内恢复；无法恢复时明确提示创建新连接。

## 5. 用户流程

### 5.1 首次使用

1. 用户访问实例。
2. 应用检查数据目录是否初始化。
3. 用户设置主密码并确认“忘记主密码无法恢复加密凭据”。
4. 应用生成 Vault key 并进入空主机工作台。
5. 用户点击“添加第一台 Server”。

### 5.2 添加并连接

1. 用户填写名称、IP/域名、端口、用户名和认证信息。
2. 用户可先点击“测试连接”。
3. 保存后，主机出现在列表中。
4. 用户点击“连接”。
5. 若是新 host key，展示地址、算法和 SHA-256 指纹。
6. 用户确认后建立交互式终端；拒绝则连接失败且不保存信任关系。

### 5.3 指纹变化

1. SSH Server 返回的 host key 与已保存指纹不一致。
2. 应用停止连接并标记为“指纹不匹配”。
3. 界面展示旧指纹和新指纹。
4. 用户只能通过进入主机安全设置、明确删除旧指纹后重新连接并确认，才能建立新信任。

## 6. 需求清单

### 6.1 功能需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-001 | 初始化 Vault | 空数据目录可创建主密码；重启后要求解锁；主密码不写入数据库。 |
| FR-002 | 新增主机 | 可保存名称、地址、端口、用户名、认证类型、分组、标签和收藏状态。 |
| FR-003 | 编辑主机 | 修改非敏感元数据或认证信息后，旧密文不会被继续使用。 |
| FR-004 | 删除主机 | 删除后列表、指纹引用和加密凭据一并清理；正在运行的会话不被静默复用。 |
| FR-005 | 密码连接 | 使用保存的用户名和密码打开交互式 shell。 |
| FR-006 | 私钥连接 | 支持常见 OpenSSH 私钥文本和可选 passphrase；解析失败给出可理解的错误。 |
| FR-007 | 主机列表 | 支持搜索、分组、收藏和最近连接排序。 |
| FR-008 | 终端交互 | 可输入、输出、复制粘贴、清屏、全屏和搜索；支持 ANSI/VT 常见控制序列。 |
| FR-009 | 多标签 | 可同时维护多个终端标签，切换标签不会丢失已连接标签的显示缓冲。 |
| FR-010 | PTY resize | 浏览器容器尺寸或字号变化后，远程终端收到正确的 rows/cols。 |
| FR-011 | 指纹校验 | 新指纹需用户确认；已知指纹变化硬失败；无跳过校验按钮。 |
| FR-012 | 断线处理 | 网络短暂中断时显示重连状态；在保留窗口内可恢复，否则可新建连接。 |
| FR-013 | 锁定 | 手动锁定或自动锁定后，不能读取凭据或新建连接；活动会话按产品设置断开。 |
| FR-014 | Docker 持久化 | 使用数据卷后，重启容器不会丢失主机元数据、密文和信任指纹。 |

### 6.2 非功能需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| NFR-001 | 部署轻量 | 单个应用容器可运行；数据只需一个可备份目录。 |
| NFR-002 | 安全存储 | 数据库和备份中不出现密码、私钥、passphrase 明文。 |
| NFR-003 | 传输安全 | 生产文档要求通过 HTTPS/WSS 反向代理访问；服务校验 WebSocket Origin。 |
| NFR-004 | 可用性 | 常见 Server 在合理网络延迟下可启动交互式终端；错误状态可恢复。 |
| NFR-005 | 可访问性 | 核心操作可键盘完成；焦点、对比度和错误消息清晰。 |
| NFR-006 | 可观测性 | 记录连接建立/关闭、认证失败、指纹拒绝和协议错误，但不记录终端内容或秘密。 |
| NFR-007 | 可测试性 | 单元、API、真实 OpenSSH 集成、浏览器 E2E 和 Docker smoke test 均可重复运行。 |

## 7. 错误与反馈规范

- 地址不可达：显示“无法连接到 Server”，附带超时/拒绝原因，不展示底层秘密或完整配置。
- 用户认证失败：显示“用户名或认证信息不正确”，提供编辑凭据入口。
- 私钥解析失败：说明格式、passphrase 或算法问题，并保留表单内容供修正。
- 指纹不匹配：高风险红色状态，展示旧/新指纹，禁止一键忽略。
- WebSocket 断开：显示重连倒计时和手动重连按钮。
- Vault 锁定：清空敏感输入控件和前端内存中的解锁材料。
- 服务端内部错误：显示可关联的 request id；日志中只保留脱敏事件。

## 8. 成功指标

首版以可验证的行为指标为主：

- 新用户从解锁到新增第一台 Server 不超过 2 分钟（不含网络排障）。
- 已保存主机从工作台到终端不超过 2 次点击。
- 终端可完成交互式程序操作，且 resize 不破坏布局。
- 主机指纹异常时没有静默放行路径。
- 容器重启后数据和主机列表完整恢复。
