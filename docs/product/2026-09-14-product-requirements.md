# 轻量 Web SSH 工作台产品与需求设计

日期：2026-09-14（基础版）

> 2026-09-15 路线图已在本仓库落地为 Web-first 生产力版本。本文保留基础版需求作为产品基线；当前交付范围、验收和明确后置项以本文第 9 节及 `docs/product/2026-09-15-ssh-productivity-release.md` 为准。

## 1. 产品定义

产品暂以“轻量 Web SSH 工作台”为工作名称，首发形态为单个 Docker 实例。它服务于需要管理多台 Linux/Unix Server 的个人开发者、运维人员和小型团队成员，通过浏览器配置并连接不同的 SSH Server。

核心承诺：

> 配置一次，之后从主机列表快速、安全地连接到任何已授权的 Server。

## 2. 用户与场景

### 2.1 首要用户

- 个人开发者：管理家用实验室、云服务器和开发环境。
- 运维/DevOps：在一个自托管入口管理开发、测试、生产主机。
- 小团队管理员：先以单用户实例使用，未来可扩展账号和权限。

### 2.2 关键场景

1. 首次部署后添加第一台 Server。
2. 已保存多台 Server，按名称、IP、标签快速搜索。
3. 在同一浏览器中打开多台 Server 的终端标签。
4. 浏览器刷新或网络波动后恢复连接。
5. 远程 Server 首次出现 host key 或 host key 发生变化。
6. 用户离开设备时锁定凭据库。
7. 在终端旁边浏览、上传和下载远程文件，不重复输入凭据。
8. 对选定主机执行带参数的批量命令，并按主机查看结果。
9. 刷新、重启或迁移后恢复工作区意图，并能复盘最近的结构化活动。

## 3. 产品目标与非目标

### 3.1 v0.1 目标

- 使用 Docker 一条命令启动。
- 支持多个 Server 配置和一键连接。
- 支持 SSH 密码、私钥和带 passphrase 的私钥。
- 提供可靠的交互式终端，兼容 `vim`、`top`、`htop`、`tmux` 等常见 TTY 程序。
- 提供分组、标签、收藏、最近连接和多终端标签。
- 对凭据、主机指纹和 WebSocket 会话建立清晰的安全边界。

### 3.1.1 当前路线图增量目标（Web-first）

- 持久化工作区意图、活动 tab、分屏布局和筛选状态；浏览器刷新时尽力复接 live session，进程重启后创建新 shell。
- 提供连接诊断、Keepalive、指数退避重连和最多四级 ProxyJump，每一跳沿用 host key policy。
- 在同一 SSH 上下文内完成 SFTP 浏览、上传、下载、整理和可取消/可重试传输。
- 通过加密 Vault bundle 完成导出、预览、冲突确认和事务导入。
- 提供参数化 Snippets、安全多主机执行、目标确认、并发/超时/输出上限和逐主机结果。
- 提供不含秘密和原始终端内容的活动摘要与批量任务审计。
- 以 shared core、wire protocol、capability 和 adapter contract 预留桌面版及 Windows/Linux/Android 客户端；本阶段不交付原生 UI。

### 3.2 v0.1 非目标

- 云端账号、云同步和多设备同步。
- 团队邀请、共享 Vault、细粒度 RBAC。
- SSH port forwarding 和 X11 forwarding。
- 终端录像、实时协作和远程桌面协议。
- RDP/VNC、Telnet、串口及其他非 SSH 协议。
- 桌面版及 Windows/Linux/Android 原生 UI（本阶段只交付跨端基础契约）。
- 浏览器内任意执行本地命令或通过 URL 传入远程主机。

非目标不是永久拒绝，而是避免首版偏离“轻量、多 Server、浏览器 SSH”主线。

## 4. 信息架构与界面

### 4.1 页面

1. **初始化/解锁页**：首次创建主密码；后续输入主密码解锁 Vault。
2. **主机工作台**：显示搜索、筛选、分组、最近连接和主机列表。
3. **新增/编辑主机抽屉**：填写连接信息和认证方式。
4. **终端工作区**：多标签终端、连接状态、终端工具栏。
5. **远程文件面板**：当前 SSH 上下文内的目录浏览、传输队列和文件操作。
6. **批量命令与活动面板**：命令预览、逐主机结果、脱敏审计和过期结果提示。
7. **设置页**：锁定、自动锁定、终端主题/字体、已信任主机指纹、工作区和加密 bundle 入口。

### 4.2 主机表单

必填：

- 主机名称
- Server IP 或域名
- SSH 端口，默认 `22`
- SSH 用户名
- 认证方式

认证字段：

- 密码认证：密码
- 私钥认证：私钥文本或文件、可选 passphrase

可选：

- 分组
- 标签
- 收藏
- 连接超时时间
- 跳板机顺序（最多四级）

表单提供“测试连接”动作，但测试过程不保存明文凭据到日志，也不默认改变主机指纹信任状态。

### 4.3 主机工作台

- 默认按最近连接排序。
- 支持名称、地址、用户名和标签搜索。
- 主机卡片展示名称、地址、端口、用户、认证类型、最近连接状态。
- 密码、私钥内容和 passphrase 永远不展示在列表和普通详情中。
- 收藏主机置顶；分组可折叠。
- 空状态直接提供“添加第一台 Server”按钮。

### 4.4 终端工作区

- 一个主机对应一个终端标签；同一主机允许打开多个标签。
- 标签显示主机名称和连接状态：连接中、已连接、重连中、已断开、失败。
- 终端使用深色默认主题，但提供浅色主题和字号调整。
- 支持复制、粘贴、全屏、终端搜索、清屏和重新连接。
- 浏览器尺寸变化同步远程 PTY 的列数和行数。
- 页面刷新后尝试在短暂保留窗口内恢复；无法恢复时明确提示创建新连接。
- 服务端重启后恢复工作区 tab 意图和布局，并创建新的 shell；不伪造原 shell 仍然存活。

### 4.5 文件、命令和活动

- 远程文件面板复用当前主机的认证、host key 和 ProxyJump 路径，支持目录列表、上传、下载、新建目录、重命名和删除。
- 上传使用远程临时文件和完成后的原子重命名；传输队列显示进度，并支持取消和失败重试。
- 批量命令在执行前展示完整目标、变量展开结果、并发、超时和是否保存输出；多主机或高风险命令需要二次确认。
- 活动页只显示结构化摘要；保存输出按主机隔离、大小封顶并按 TTL 过期。

## 5. 用户流程

### 5.1 首次使用

1. 用户访问实例。
2. 应用检查数据目录是否初始化。
3. 用户设置主密码并确认“忘记主密码无法恢复加密凭据”。
4. 应用生成 Vault key 并进入空主机工作台。
5. 用户点击“添加第一台 Server”。

### 5.2 添加并连接

1. 用户填写名称、IP/域名、端口、用户名和认证信息。
2. 用户可先点击“测试连接”。
3. 保存后，主机出现在列表中。
4. 用户点击“连接”。
5. 若是新 host key，展示地址、算法和 SHA-256 指纹。
6. 用户确认后建立交互式终端；拒绝则连接失败且不保存信任关系。

### 5.3 指纹变化

1. SSH Server 返回的 host key 与已保存指纹不一致。
2. 应用停止连接并标记为“指纹不匹配”。
3. 界面展示旧指纹和新指纹。
4. 用户只能通过进入主机安全设置、明确删除旧指纹后重新连接并确认，才能建立新信任。

## 6. 需求清单

### 6.1 功能需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| FR-001 | 初始化 Vault | 空数据目录可创建主密码；重启后要求解锁；主密码不写入数据库。 |
| FR-002 | 新增主机 | 可保存名称、地址、端口、用户名、认证类型、分组、标签和收藏状态。 |
| FR-003 | 编辑主机 | 修改非敏感元数据或认证信息后，旧密文不会被继续使用。 |
| FR-004 | 删除主机 | 删除后列表、指纹引用和加密凭据一并清理；正在运行的会话不被静默复用。 |
| FR-005 | 密码连接 | 使用保存的用户名和密码打开交互式 shell。 |
| FR-006 | 私钥连接 | 支持常见 OpenSSH 私钥文本和可选 passphrase；解析失败给出可理解的错误。 |
| FR-007 | 主机列表 | 支持搜索、分组、收藏和最近连接排序。 |
| FR-008 | 终端交互 | 可输入、输出、复制粘贴、清屏、全屏和搜索；支持 ANSI/VT 常见控制序列。 |
| FR-009 | 多标签 | 可同时维护多个终端标签，切换标签不会丢失已连接标签的显示缓冲。 |
| FR-010 | PTY resize | 浏览器容器尺寸或字号变化后，远程终端收到正确的 rows/cols。 |
| FR-011 | 指纹校验 | 新指纹需用户确认；已知指纹变化硬失败；无跳过校验按钮。 |
| FR-012 | 断线处理 | 网络短暂中断时显示重连状态；在保留窗口内可恢复，否则可新建连接。 |
| FR-013 | 锁定 | 手动锁定或自动锁定后，不能读取凭据或新建连接；活动会话按产品设置断开。 |
| FR-014 | Docker 持久化 | 使用数据卷后，重启容器不会丢失主机元数据、密文和信任指纹。 |
| FR-015 | 工作区恢复 | 持久化 tab 意图、活动 tab、分屏比例和筛选状态；不持久化 terminalId、凭据或会话 token。 |
| FR-016 | 加密 bundle | 使用独立导出密码加密导出；导入先预览冲突，再由用户确认并以事务合并。 |
| FR-017 | ProxyJump | 支持最多四级有序跳板；每一跳独立执行 host key 校验，环和跨 owner 引用必须拒绝。 |
| FR-018 | SFTP 文件闭环 | 在同一 SSH 上下文内完成列目录、上传、下载、新建目录、重命名和删除。 |
| FR-019 | 可靠传输 | 上传先写临时文件后原子重命名；队列提供进度、取消和失败重试，半文件不得替代目标文件。 |
| FR-020 | Snippets | 支持 Vault 加密的命令片段和显式 `{{variable}}` 参数；缺失或多余参数必须拒绝。 |
| FR-021 | 安全批量执行 | 服务端重新校验目标主机；默认并发 4、最大 16、单主机超时 60 秒、输出上限 256 KiB；多主机和高风险命令需确认。 |
| FR-022 | 逐主机结果 | 批量任务隔离每台主机的状态、退出码、输出和错误，单台失败不能隐藏其他结果。 |
| FR-023 | 活动与审计 | 提供连接、工作区、SFTP 和批量任务的脱敏结构化摘要；不记录交互式终端原始内容。 |
| FR-024 | 结果 TTL | 选择保存的批量输出按主机隔离并在 TTL 后清理；活动页对已过期结果给出明确提示。 |
| FR-025 | 跨端契约 | shared core 不依赖 Node、DOM、React 或 ssh2；Web 通过 adapter 实现，桌面/Windows/Linux/Android 后续替换 transport 和 secret store。 |

### 6.2 非功能需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| NFR-001 | 部署轻量 | 单个应用容器可运行；数据只需一个可备份目录。 |
| NFR-002 | 安全存储 | 数据库和备份中不出现密码、私钥、passphrase 明文。 |
| NFR-003 | 传输安全 | 生产文档要求通过 HTTPS/WSS 反向代理访问；服务校验 WebSocket Origin。 |
| NFR-004 | 可用性 | 常见 Server 在合理网络延迟下可启动交互式终端；错误状态可恢复。 |
| NFR-005 | 可访问性 | 核心操作可键盘完成；焦点、对比度和错误消息清晰。 |
| NFR-006 | 可观测性 | 记录连接建立/关闭、认证失败、指纹拒绝、SFTP 生命周期和批量摘要，但不记录终端内容或秘密。 |
| NFR-007 | 可测试性 | 单元、API、真实 OpenSSH 集成、浏览器 E2E、重启边界和构建检查均可重复运行。 |
| NFR-008 | 跨平台基础 | Node 与浏览器编译目标共享同一领域模型、状态语义、错误码、capability 和安全确认规则。 |

## 7. 错误与反馈规范

- 地址不可达：显示“无法连接到 Server”，附带超时/拒绝原因，不展示底层秘密或完整配置。
- 用户认证失败：显示“用户名或认证信息不正确”，提供编辑凭据入口。
- 私钥解析失败：说明格式、passphrase 或算法问题，并保留表单内容供修正。
- 指纹不匹配：高风险红色状态，展示旧/新指纹，禁止一键忽略。
- WebSocket 断开：显示重连倒计时和手动重连按钮。
- Vault 锁定：清空敏感输入控件和前端内存中的解锁材料。
- 服务端内部错误：显示可关联的 request id；日志中只保留脱敏事件。

## 8. 成功指标

首版以可验证的行为指标为主：

- 新用户从解锁到新增第一台 Server 不超过 2 分钟（不含网络排障）。
- 已保存主机从工作台到终端不超过 2 次点击。
- 终端可完成交互式程序操作，且 resize 不破坏布局。
- 主机指纹异常时没有静默放行路径。
- 容器重启后数据和主机列表完整恢复。

## 9. 当前路线图交付与后置边界

### 9.1 已交付（2026-09-15 Web-first）

- P0：服务端工作区快照、tab 意图和布局恢复；Vault bundle 加密导出、预览、冲突确认和事务导入；连接阶段诊断、重连和 ProxyJump。
- P1：复用 SSH 连接资源的 SFTP 浏览与传输队列；临时文件 + 原子重命名；取消、重试和路径越界保护；加密 Snippets、变量展开和安全多主机执行。
- P2：逐主机批量结果、可选输出保存、活动摘要、审计筛选、脱敏和 TTL 过期提示。
- 跨端基础：shared core 模型、状态机、错误码、capability 和 ports；Web 使用 HTTP/WSS adapter，桌面版以及 Windows/Linux/Android 后续替换平台 transport 和 secret store。

### 9.2 当前不承诺

- 端口转发、X11、RDP/VNC、Telnet、串口、云同步、第三方同步、团队 RBAC、SSO、实时协作和原生桌面/移动 UI。
- 交互式终端原始输入输出录制，以及应用进程重启后原远程 shell 或内存任务的继续执行。
